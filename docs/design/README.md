# Design briefs

Written by the `ui-designer` agent (skill: `visual-direction`). One file per feature or page: `docs/design/<slug>.md`.

A brief is **approved** when the owner or main session adds `Status: approved` at the top. The `frontend-engineer` implements only approved briefs.

Required sections: Status, Goal and audience, Content inventory, Composition (per breakpoint), Typography, Colour and surfaces, Interaction and motion, States (empty, loading, error, long text), Accessibility notes, Tokens used or proposed, Out of scope.
