# Kui Anasy: архитектурный аудит и план (04.11.2026)

Аудит провели четыре исполнителя: CSS (Haiku), мёртвый код и зависимости (Haiku), frontend/UX (Sonnet), backend и инфраструктура (Opus). Ключевые утверждения перепроверены вручную: grep и чтение кода. Срок по договору — **16.11.2026**, осталось 12 дней.

## 1. Стек (фактический)

- **Client:** React 18 + Vite 6, без роутера (hash-роутинг вручную в `App.jsx`), без TypeScript, ESLint и тестов. Иконки из двух библиотек: `react-icons` и `lucide-react`. Lenis для плавной прокрутки, `qrcode`.
- **Server:** Express + pg + zod. Одна таблица контента `content_pages`, страница хранит блоки в JSONB. С 04.11 добавлены `admin_users`, `admin_sessions`, `audit_log`, серверная модерация и e2e-тест API (23/23).
- **Деплой сейчас:** Vercel + Render. По договору нужен один VPS: Nginx + Node + PostgreSQL.

## 3. Что сохраняем

- Серверную модель «страница = упорядоченные блоки в JSONB». Она верная, её расширяем, а не переписываем.
- Серверную авторизацию, модерацию и аудит из этапа 1.
- `HeritageMap`, `Header` (после разгрузки) и визуальное направление Heritage Editorial.
- Ко-локированные CSS-файлы (`HeritageMap.css`, `AuditLogView.css`) — это целевой паттерн.
- Hash-URL: на 12 дней роутер-библиотека не окупается.

## 4. Архитектурные решения

**A1. Весь видимый контент живёт в CMS.** Выделенные JSX-страницы превращаем в seed-блоки, после чего удаляем их JSX. Особые макеты собираются из новых типов блоков, а не из отдельных страниц.

**A2. Переводы.** Общий идентификатор — `slug`. Колонки страницы остаются казахской (базовой) версией. Новая колонка `translations jsonb` хранит `{ru:{title,description,blocks}, en:{…}}`. Если перевода нет, показывается kk с пометкой. Черновики модерации и аудит работают с той же структурой.

**A3. Персона — это страница.** У каждого күйші, жырау и әнші своя страница (`people-kuyshi/kurmangazy`) с блоком `person` (годы, регион, школа, статус, произведения, портрет, аудио). Канон-страницы становятся списками дочерних страниц, а карта берёт персон из API по `person.region`. Так у каждой персоны появляется URL, QR и перевод — без новой таблицы.

**A4. Реестр блоков вместо if-цепочки.** `blocks/index.jsx`: тип → компонент. Новые типы: `person`, `audio`, `video` (YouTube, nocookie), `gallery`, `faq`, `schedule`, `person-grid`.

**A5. Свой маленький роутер** (`app/router.js`, ~60 строк): `#/ru/slug`, компонент `<Link>` как настоящий `<a>`, 404, `useDocumentMeta` (title и `html lang`). Язык попадает в URL, поэтому QR ведёт на нужный язык.

**A6. Контексты вместо prop drilling:** `useSite()` (страницы, сессия, тема), `useT()` (UI-строки из `i18n/{kk,ru,en}.js`).

**A7. Дизайн-система.**
- `styles/tokens.css`: только палитра обложки. `terra`, `plum` и `wine` удаляются.
- Шкалы отступов и размеров шрифта, 3 брейкпоинта (480 / 768 / 1024), шкала z-index.
- Один шрифт: предложена Literata (OFL, проверены все казахские буквы, `docs/font-specimen.png`). Логотип — изображение, а не шрифт.
- CSS страниц и компонентов лежит рядом с ними; `admin.css` грузится только вместе с админкой.

**A8. Медиа.** Загрузка через presigned PUT напрямую в Cloudflare R2 (сервер только подписывает и проверяет тип и размер). Видео — YouTube-embed по ID.

**A9. Никакого фейка.** Аудио-кнопки появятся только вместе с реальным `audio`-блоком. Форма Muragerler получает настоящий endpoint `POST /api/applications` с хранением в БД и разделом «Өтінімдер» в админке. Неподтверждённые факты скрываются до подтверждения заказчиком.

**A10. Инструменты.** Минимальный ESLint (react-hooks, jsx-a11y) — не блокирует сборку. E2E-тест API переезжает в репо (`server/test/`). Скрипт `scripts/verify.mjs` проверяет полноту i18n-ключей и наличие kk у всех страниц. Lenis убираем: старшая аудитория, конфликт с модалками.

## 6. Решения за владельцем и заказчиком

1. **Шрифт:** утвердить Literata как единственный (образец: `docs/font-specimen.png`).
2. **Неподтверждённые факты** (ISBN, менторы, расписание, «150+», автобусы, номера стел, справки о двух людях в подсказках) — получить источник у заказчика или убрать. До ответа скрываем.
3. **Публичный репо:** сделать приватным? Убрать из git PDF-книгу и docx заказчика (`git rm --cached`, файлы на диске останутся). Удалить из репо 37 MB неиспользуемых шрифтов.
4. **Прод-ключ:** убедиться, что `ADMIN_TOKEN` на Render/VPS не равен старому ключу из истории git.
5. **Данные персон для 4 регионов карты** (Сарайшық, Маңғыстау, Ұлытау, Тарбағатай) и переводы RU/EN — от заказчика.
